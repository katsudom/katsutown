# Katsudom Town — architecture & build contract

This file is the shared contract. Every module is built against the signatures
below, so the pieces can be written independently and still fit together.

## Stack

- **Phaser 3.90** + **TypeScript 5.9**, bundled by **Vite 6** (multi-page build).
- Two entry points: `index.html` → the game, `classic.html` → the plain React +
  Tailwind portfolio at `/classic`.
- No backend. `npm run build` emits a static `dist/`.
- `npm run assets` regenerates every PNG from `tools/generate-assets.mjs`.
  It runs automatically before `dev` and `build`.

## Hard rendering rules

| Thing            | Value                                                |
| ---------------- | ---------------------------------------------------- |
| Source tile      | 16×16 px                                             |
| Render scale     | 3× — applied as **camera zoom** on world scenes      |
| Canvas           | 960×720 (= 20×15 tiles at 3×)                        |
| Scale mode       | `Phaser.Scale.FIT` + `CENTER_BOTH`, `pixelArt: true` |
| Character frames | 16×16, 4 directions × 3 frames, sheet is 48×64       |
| Movement         | grid-locked, `MOVE_MS` (160 ms) per tile             |

World scenes zoom 3×. **UI scenes run unzoomed** and address the full 960×720
space — that keeps the bitmap font crisp. Never zoom a UI scene.

## Files and ownership

```
tools/generate-assets.mjs      asset generator (owns every PNG + the font)
src/game/palette.json          colour source of truth (read by TS and by Node)
src/game/palette.ts            typed palette accessors
src/game/config.ts             TILE_SIZE, RENDER_SCALE, SCENES, DEPTH, MOVE_MS…
src/game/types.ts              shared contracts (MapDef, Interactable, …)
src/game/assets.ts             asset manifest — paths, sizes, frame layouts
src/game/generated/tiles.ts    GENERATED by the asset script: named tile indices
src/game/data/content.ts       all portfolio copy (already written — do not invent facts)
src/game/data/maps.ts          MapDef per map: npcs, interactables, warps
public/assets/maps/<id>.json   Tiled-format tilemap per MapId
src/game/scenes/               Boot, Title, Ui, World, Menu
src/game/systems/              settings, audio, input, player, dialogue, touch
src/classic/                   React + Tailwind plain portfolio
```

Nothing outside `assets.ts` may reference an asset path as a string literal.

## Scene graph

```
Boot ──> Title ──> World  (+ Ui always running on top)
                     │
                     └─> Menu (launched over World, pauses it)
```

- **Boot** — loads the manifest in `assets.ts`, builds animations, shows a
  progress bar, then starts `Title`.
- **Title** — "Katsudom Town" logo, subtitle "Dominic Pham · CS @ OU",
  blinking "Press Start", and a visible "Skip to regular portfolio" link that
  navigates to `classic.html`.
- **World** — one scene for every map. Re-entering is a map _swap_, not a new
  scene, driven by `MapId`. Overworld and all interiors use this scene.
- **Ui** — always-on overlay: dialogue box, interact prompt, location banner,
  touch controls. Never destroyed.
- **Menu** — launched over `World`, pauses it, Esc closes.

## Tilemap conventions

Every `public/assets/maps/<id>.json` is Tiled-format JSON, 16×16 tiles, using
the single tileset image `assets/tiles/tiles-town.png` and these **exact** layer
names:

| Layer      | Type | Purpose                                             |
| ---------- | ---- | --------------------------------------------------- |
| `ground`   | tile | base terrain, always filled                         |
| `decor`    | tile | flowers, path edges, rugs — drawn above ground      |
| `overhang` | tile | tree canopy / roof edges drawn **above** the player |
| `collide`  | tile | any non-zero tile blocks movement; never rendered   |

`collide` is the only source of collision truth. Buildings, props and NPC tiles
must each be blocked there. Warp tiles must be walkable.

Named tile indices come from `src/game/generated/tiles.ts` (produced by the
asset script) — never hard-code a raw tile number.

## World layout (overworld, 60×45 tiles ≈ 3 screens wide)

- Spawn: outside Dominic's House, centre-west.
- Town square with fountain + Welcome Sign in the middle.
- Four project locations ring the square: The Archive (NW), Server Shed (SW),
  Free Food Finder truck (SE), Ascent trailhead (E/NE).
- North path → Hacklahoma Clubhouse. East path → Campus Gate + Admissions.
- Trees, fences and a creek bound the map on all four sides.

Fast-travel targets in `MAP_MARKERS` (`data/content.ts`) must land on walkable
overworld tiles.

## Maps

`overworld`, `house`, `archive`, `truck`, `trail`, `shed`, `clubhouse`,
`admissions`. **Every interior has an exit warp back to the overworld**, placed
on the tile the player entered from and facing out.

## Content rules

- All copy comes from `data/content.ts`. Do not invent facts about Dominic.
- Each project interior exposes **one interactable per bullet** plus a project
  card object. Several projects have 5 bullets; carrying all of them matters
  more than hitting the spec's "3–4 objects" guideline exactly.
- Art is **original**, drawn in the classic GBA-era top-down RPG style. No
  third-party sprites, no trademarked names or characters.

## Testing hooks

In a **dev build only**, `src/main.ts` exposes the Phaser game as
`window.__katsudom`. `import.meta.env.DEV` is statically false in a production
build, so the whole block is dead-code-eliminated and never ships — verified by
asserting `window.__katsudom` is undefined on the built site.

This exists so an automated harness can read real game state (active scenes,
the player's tile, `dialogueOpen`) instead of inferring it from pixels. Useful
entry points on `WorldScene` for such a harness:

| Member            | Use                                                 |
| ----------------- | --------------------------------------------------- |
| `mapId`           | the map currently loaded                            |
| `warpTo(t,sfx,b)` | jump to any map/tile, bypassing walking             |
| `interactByTile`  | `Map<"x,y", Interactable>` for the current map      |
| `isBlocked(x,y)`  | collision query, for placing a probe on a free tile |
| `tourActive`      | whether the guided tour is running                  |
| `player`          | `.tileX`, `.tileY`, `.facing`, `.teleport()`        |

`TouchControls.measure()` returns the on-screen CSS pixel size of the D-pad
arrow, the A button and the menu button, so the 44px touch-target floor can be
asserted rather than eyeballed.

Note that a **hidden** browser pane throttles `requestAnimationFrame` to ~3 fps
and then to zero, which freezes Phaser's game loop and makes input appear
broken. Drive the game headlessly, or keep the pane visible.

## Acceptance criteria (the reviewer checks these)

1. `npm run dev` serves the game; `npm run build` emits a static site.
2. Every building, NPC, sign and menu item works.
3. Playable on desktop and at phone size (touch D-pad + A button).
4. No console errors. Loads in under 3 seconds.
5. All content matches the spec exactly; nothing invented.
